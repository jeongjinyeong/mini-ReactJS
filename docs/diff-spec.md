# Diff 명세

두 JavaScript 객체 트리의 모든 노드를 방문하고 같은 숫자 `key`를 가진 노드끼리 비교한다. 기존 텍스트 노드의 글자나 숫자 표시값이 달라지면 변경 목록에 기록한다. 첫 구현은 트리 전체를 비교하는 단순한 방식을 사용한다.

## 1. 입력과 결과

Diff의 호출 계약은 `diff(baseTree, targetTree)`다. 두 인자 모두 [VDOM 생성 명세](./project-spec.md)의 요소·텍스트 객체 형식을 사용한다.

| 인자 | 의미 | 만드는 방법 |
|---|---|---|
| `baseTree` | 현재 실제 DOM에 표시된 값의 복사본 | `createVDOM(root, state, [])`로 갱신 함수 없이 생성한다. |
| `targetTree` | 이번에 표시할 값이 모두 들어간 목표 VDOM | `createVDOM(root, state, updates)`로 필요한 갱신 함수를 모두 실행해 생성한다. |

이벤트가 상태를 바꾼 뒤 두 트리를 만들 수 있다. 두 호출에 같은 변경 후 `state`를 전달해도 기준 트리의 표시값은 실제 DOM에서 읽는다. 두 복사는 같은 원본 루트와 같은 DOM 상태를 기준으로 한다.

각 트리의 `key`는 고유한 정수다. 두 트리는 대응 노드의 `key`, `kind`, 태그, 속성, 위치와 자식 순서가 같은 유효한 VDOM을 전제로 한다. 차이가 날 수 있는 필드는 기존 텍스트 노드의 `value`다.

반환값은 변경 기록의 배열이다.

| 필드 | 자료형 | 의미 |
|---|---|---|
| `key` | 숫자 | 변경된 텍스트 노드의 key |
| `oldValue` | 문자열 | 기준 트리의 `value` |
| `newValue` | 문자열 | 목표 트리의 `value` |

## 2. 기능 요구사항

### FR-DIFF-001 두 비교 입력 준비

- 호출자는 현재 실제 DOM을 기준 트리로 복사하고 같은 DOM에서 목표 트리를 생성한다.
- 목표 트리에는 그 상태에 연결된 모든 갱신 함수의 결과가 담겨 있어야 한다. 두 트리를 준비한 뒤 Diff에 전달한다.
- **완료 조건**은 실제 DOM에 `수량: 1`이 표시된 상태에서 `count`를 `2`로 바꿨을 때 기준 트리에 `수량: 1`, 목표 트리에 `수량: 2`가 담기는 것이다.

### FR-DIFF-002 모든 노드를 같은 key로 비교

1. 기준 트리의 루트부터 모든 자식 노드를 방문해 `key`로 기준 노드를 찾을 수 있는 조회표를 만든다.
2. 목표 트리의 루트를 먼저 방문하고, 각 노드의 `children` 배열 순서대로 하위 트리를 끝까지 방문한다.
3. 방문한 목표 노드마다 같은 `key`의 기준 노드를 찾고 `kind`를 확인한다. 요소 노드도 조회하고 그 아래 자식을 방문한다.
4. 텍스트 노드는 두 `value`를 문자열 그대로 비교한다. 값이 달라진 경우 변경 기록을 하나 추가한다.

**완료 조건**은 깊게 중첩된 텍스트의 변경도 발견하고, 여러 기록을 목표 트리에서 방문한 순서대로 반환하는 것이다.

### FR-DIFF-003 변경 목록 반환

- Diff는 두 트리의 값을 읽어 새 변경 목록을 반환한다. 두 입력의 노드, 값, 자식 배열은 비교 전후에 그대로다.
- 같은 `key`의 텍스트 `value`가 같으면 그 노드의 변경 기록을 만들지 않는다. 모든 텍스트 값이 같으면 `[]`를 반환한다.
- **완료 조건**은 변경된 텍스트만 목록에 있고 동일한 버튼 문구 등은 목록에 없으며, 입력 트리가 비교 전과 같은 것이다.

### FR-DIFF-004 비교할 수 없는 노드 처리

- 순회 중 필수 숫자 `key`가 없거나, 목표 노드의 `key`에 대응하는 기준 노드가 없거나, 같은 `key`인데 두 노드의 `kind`가 다르면 `TypeError`를 발생시킨다. 오류 메시지에 실패 이유와 확인 가능한 key를 담는다.
- 오류가 발생하면 비교를 중단한다. 고유한 key와 고정된 트리 구조·속성은 호출자의 입력 계약이다.
- **완료 조건**은 대응 key가 없거나 `kind`가 다른 노드를 만나면 변경 목록 대신 오류가 전달되는 것이다.

## 3. 검증 예시

같은 루트 아래에서 수량 텍스트, 두 배 텍스트, 버튼 문구를 순서대로 방문한다고 가정한다. `count`가 1에서 2로 바뀌면 다음 입력으로 비교한다.

| 노드 | 예시 key | 기준 `value` | 목표 `value` |
|---|---:|---|---|
| 수량 텍스트 | 12 | `수량: 1` | `수량: 2` |
| 두 배 텍스트 | 14 | `두 배: 2` | `두 배: 4` |
| 버튼 텍스트 | 16 | `추가` | `추가` |

예상 변경 목록은 두 항목이다.

```json
[
  { "key": 12, "oldValue": "수량: 1", "newValue": "수량: 2" },
  { "key": 14, "oldValue": "두 배: 2", "newValue": "두 배: 4" }
]
```

| 확인 항목 | 기대 결과 |
|---|---|
| 위 예시 비교 | 12, 14번 기록이 순서대로 나온다. 버튼 문구와 두 입력 트리는 그대로다. |
| 같은 DOM에서 갱신 없이 만든 두 복사본 비교 | `[]`가 나온다. |
| `<div><section><p>수량: 1</p></section></div>`의 깊은 텍스트를 목표 트리에서 `수량: 2`로 변경 | 해당 텍스트의 key와 이전 값, 새 값이 기록된다. |
| 목표 트리의 노드에 대응하는 기준 key가 없거나 같은 key의 노드 종류가 다름 | 실패 이유를 포함한 `TypeError`가 발생한다. |

## 4. 결정 근거

| 구분 | 내용 |
|---|---|
| 사용자 결정 | 고유한 숫자 key로 노드를 대응시킨다. 전체 노드를 비교해 변경점 목록을 얻는다. 성능 최적화보다 단순한 구현을 우선한다. 이번 버전의 변경 대상은 기존 텍스트의 글자와 숫자다. |
| 명세 기본안 | 현재 DOM에서 만든 기준 복사본과 갱신된 목표 VDOM을 입력으로 삼는다. key 조회표, 목표 트리 방문 순서, `diff` 함수명과 기록 필드, 비교 오류의 전달 방식을 정했다. |

위 예시는 구현 결과를 확인할 기준이며 실행 검증은 예정 상태다.
