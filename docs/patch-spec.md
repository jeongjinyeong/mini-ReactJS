# Patch 명세

Diff에 기록된 텍스트 변경만 실제 DOM에 반영한다. 첫 버전에서는 해당 `Text` 노드의 문자열 값을 바꾼다. 노드 객체와 숫자 key, 태그·속성·자식 위치는 그대로 유지된다. 브라우저는 변경된 DOM의 텍스트를 화면에 표시한다.

## 1. 호출 계약

호출 형식은 `patch(root, changes)`다. 호출자는 같은 원본 DOM에서 기준 VDOM과 목표 VDOM을 만들고, `diff(baseTree, targetTree)`로 얻은 목록을 `patch`에 전달한다. [VDOM 생성 명세](./project-spec.md), [Diff 명세](./diff-spec.md)

| 항목 | 계약 |
|---|---|
| `root` | 두 VDOM을 만들 때 전달한 원본 HTML `Element`다. 적용 대상은 이 루트 아래의 실제 `Text` 노드다. |
| `changes` | Diff가 반환한 `{ key, oldValue, newValue }` 배열이다. `key`는 고유한 정수이고, `oldValue`와 `newValue`는 서로 다른 문자열이다. |
| 반환값 | 실제 값을 바꾼 노드 수다. 빈 변경 목록의 반환값은 `0`이다. |

## 2. 기능 요구사항

### FR-PATCH-001 입력 확인

- 호출자가 원본 `root`와 `changes`를 전달한다. 루트 타입, 배열 여부, 각 항목의 key와 두 문자열을 검사한다. key 중복과 이전 값·새 값이 같은 항목도 형식 오류로 처리한다.
- 입력 형식이 잘못되면 `TypeError`를 던진다. 유효한 빈 목록이면 `0`을 반환한다.
- **완료 조건**은 빈 목록에 대해 `0`을 얻고, 형식이 잘못된 목록에 대해 DOM 값의 변화 없이 오류를 받는 것이다.

### FR-PATCH-002 대상 조회와 사전 검사

1. `root` 아래의 실제 `Text` 노드를 한 차례 순회한다. 각 노드에서 VDOM의 `getNodeKey(node)`로 key를 얻고 목록에 있는 대상의 참조를 모은다.
2. 각 기록에 대응하는 `Text`가 루트 아래에 있는지, 그 노드의 현재 `data`가 `oldValue`와 문자열 그대로 일치하는지 확인한다.
3. 대상이 없거나 현재 값이 다르면 실패 이유와 해당 key를 포함한 `Error`를 던진다. 모든 항목이 검사를 통과한 뒤에만 실제 값을 바꾸는 단계로 넘어간다.

**완료 조건**은 두 번째 항목의 검사에 실패해도 첫 번째 항목을 포함해 이번 목록의 어떤 DOM 값도 바뀌지 않는 것이다.

### FR-PATCH-003 기록된 텍스트 값 적용

- 검사에서 확보한 `Text` 객체를 사용해, 변경 목록 순서대로 각 노드의 `data`에 `newValue`를 대입한다.
- `Text` 객체와 숫자 key를 유지한다. DOM 쓰기는 목록에 있는 `Text`의 `data`에만 일어난다. 주변 요소와 속성, 자식 순서, 목록에 없는 텍스트 값은 보존된다.
- 모든 항목을 적용하면 적용 건수를 반환한다.
- **완료 조건**은 변경 두 건을 적용하면 `2`를 반환하고, 두 텍스트가 목표 값으로 바뀌며, 적용 전후에 각각 같은 노드 객체와 key가 확인되는 것이다.

## 3. 검증 예시

원본 DOM의 수량과 두 배 값이 각각 `수량: 1`, `두 배: 2`이고, Diff가 key 12와 14의 변경을 이 순서로 반환했다고 가정한다.

| 실제 노드 | 예시 key | 적용 전 | 적용 후 |
|---|---:|---|---|
| 수량 텍스트 | 12 | `수량: 1` | `수량: 2` |
| 두 배 텍스트 | 14 | `두 배: 2` | `두 배: 4` |
| 버튼 텍스트 | 16 | `추가` | `추가` |

| 확인 항목 | 기대 결과 |
|---|---|
| 위 변경 목록 적용 | `2`를 반환한다. 수량·두 배 값만 바뀌고 버튼과 나머지 DOM은 유지된다. key 12·14의 `Text` 객체를 적용 전후에 각각 비교하면 같고, `getNodeKey`도 같은 값을 반환한다. |
| 성공한 Patch 뒤 기준 VDOM 재생성 | 같은 원본 DOM을 `createVDOM(root, state, [])`로 복사한 뒤 같은 목표 VDOM과 Diff하면 `[]`가 나온다. |
| 빈 변경 목록 | `0`을 반환하고 실제 DOM은 그대로다. |
| 목록에 적힌 key의 `Text`가 `root` 아래에 없음 | 해당 key를 알려 주는 오류가 발생하고 실제 DOM은 그대로다. |
| key 12의 현재 값은 일치하나 key 14의 현재 값이 `oldValue`와 다름 | key 14의 값 불일치 오류가 발생한다. key 12의 수량도 적용 전인 `수량: 1`을 유지한다. |
| 변경 항목의 `newValue`가 문자열이 아님 | `TypeError`가 발생하고 실제 DOM은 그대로다. |

## 4. 결정 근거

| 구분 | 내용 |
|---|---|
| 사용자 결정 | Diff에 기록된 변경만 화면에 반영한다. 첫 버전은 기존 글자와 숫자만 갱신하고 구조·속성·위치를 유지한다. |
| 명세 기본안 | `patch(root, changes)` 호출과 적용 건수 반환, `getNodeKey`를 이용한 대상 조회, 전체 목록 사전 검사, 기존 `Text.data`를 목록 순서대로 갱신하는 방식. |

위 예시는 구현 결과를 확인할 완료 기준이며 실행 검증은 예정 상태다.
