# Phase 2. Component · State · Hooks

## 목표

`Component`, `State`, `Hooks`를 직접 구현하고, 이를 활용해 동작하는 웹 페이지를 만든다.

## Component

컴포넌트는 UI를 나누는 단위다. 각 컴포넌트는 자신의 로직과 렌더링을 담당하며, 함수형으로 구현한다.

### 컴포넌트의 반환값과 자식 조합

- 각 함수형 컴포넌트는 VDOM 노드(`VNode`) 하나를 반환한다. 요소를 표현할 때는 `VElement`를, 텍스트를 표현할 때는 `VText`를 반환한다.
- 부모 컴포넌트는 자식 컴포넌트가 반환한 `VNode`를 받아 자신이 반환할 요소 노드의 `children` 배열에 넣는다.

### FunctionComponent

함수형 컴포넌트를 감싸는 `FunctionComponent` 클래스를 구현한다.

| 멤버 | 역할 |
| --- | --- |
| `hooks` | 상태를 저장하는 배열 |
| `mount()` | 처음 렌더링 |
| `update()` | 상태 변경 후 다시 렌더링 |

### 상태와 Hook 사용 범위

- 상태 관리와 Hook 사용은 최상위 컴포넌트(루트 컴포넌트)에서만 가능하다.
- 자식 컴포넌트는 부모가 전달한 `props`만 사용하는 상태 없는 순수 함수로 구현한다. 이 구조는 `Lifting State Up` 패턴을 따른다.

## State

상태는 변경할 수 있는 데이터다. 상태가 바뀌면 화면을 자동으로 다시 렌더링한다.

## Hooks

Hooks는 함수형 컴포넌트에서 상태와 생명주기를 사용할 수 있게 한다. 컴포넌트 함수가 다시 실행되어도 상태를 유지하는 것이 핵심이다.

최소 구현 대상은 다음과 같다.

- `useState`
- `useEffect`
- `useMemo`

### 공통 Hook 규칙

- Hook의 저장 정보는 루트 컴포넌트의 인스턴스별로 관리한다.
- 각 `useState`는 자신의 상태가 저장된 위치를 기억한다. 다시 렌더링할 때 호출 순서가 달라져도 기억한 위치에서 자신의 상태를 읽는다.

### useState

- 초기값은 `mount()`가 처음 렌더링할 때 화면에 표시할 기본 상태로 사용한다.
- 상태를 현재 값과 같은 값으로 다시 설정하면 화면을 갱신하지 않는다.
- 여러 상태 중 하나를 변경해 다시 렌더링하면, 변경한 상태는 새 값을 사용하고 다른 상태는 각자의 현재 값을 유지한다.

예를 들어 배송 방법을 빠른 배송으로 선택한 뒤 수량을 1에서 2로 바꾸면, 화면에는 수량 2와 빠른 배송이 표시된다.

### useEffect

- 첫 `useEffect` 작업은 `mount()`가 첫 화면을 표시한 직후에 실행한다.
- 다시 렌더링할 때 의존 값이 이전과 같으면 기존 작업을 이어 간다.
- 의존 값이 달라지면 이전 작업을 먼저 정리한 뒤 새 의존 값으로 작업을 시작한다.

예를 들어 선택한 상품의 재고를 확인하는 타이머가 있다면, 수량만 바뀌었을 때는 기존 타이머를 계속 사용한다. 상품이 사과에서 배로 바뀌면 사과 타이머를 중지한 뒤 배 재고 확인 타이머를 시작한다.

### useMemo

- 첫 렌더링에서는 계산에 필요한 상태값을 `useState`로 읽은 뒤, `useMemo`로 VDOM 구성에 사용할 값을 계산한다. 계산 결과와 의존 값을 함께 저장한다.
- 이후 렌더링에서는 현재 의존 값과 저장된 의존 값을 비교한다. 의존 값이 같으면 계산을 건너뛰고 저장한 결과를 사용한다.
- 의존 값이 달라지면 다시 계산하고 새 결과와 의존 값을 저장한다. VDOM을 구성할 때 새 결과를 사용한다.

## 화면 이벤트와 상태 변경

- 버튼을 한 번 클릭하면 연결된 이벤트 핸들러가 한 번 실행된다. 다시 렌더링한 뒤에도 이 규칙을 적용한다.
- 이벤트 핸들러는 새 값을 계산해 루트 컴포넌트의 `useState`에서 받은 상태 변경 함수에 전달한다.
- 상태값이 달라지면 `update()`를 한 번 실행한다. 새 상태값을 기준으로 VDOM을 다시 만들고, Diff에서 찾은 화면 변경점을 한 번의 갱신으로 모두 반영한다.

## Phase 1과의 연계

[Phase 1](./project-spec.md)에서 구현한 Virtual DOM, Diff, Patch를 활용한다.

### 첫 렌더링

1. `mount()`는 루트 컴포넌트가 반환한 첫 VDOM을 실제 DOM으로 변환해 화면에 표시한다.
2. 첫 화면에 반영한 VDOM을 이후 Diff의 비교 기준으로 삼고, 히스토리의 첫 항목으로 저장한다.

### 상태 변경 후 렌더링

1. `update()`는 변경된 상태를 반영한 새 VDOM을 생성한다.
2. 직전에 화면 반영을 마친 VDOM과 새 VDOM을 비교한다 (`Diff`). 첫 `update()`에서는 `mount()`로 화면에 표시한 VDOM을 기준으로 삼는다.
3. Diff에서 변경점을 찾지 못하면 실제 DOM 쓰기는 0건이다. 새 VDOM을 폐기하고 기존 비교 기준과 히스토리를 유지한다.
4. 변경점이 있으면 바뀐 부분만 실제 DOM에 반영한다 (`Patch`). Patch가 끝나면 새 VDOM을 다음 비교의 기준으로 삼고 히스토리에 저장한다.

VDOM을 히스토리에 저장할 때는 Phase 1과 같은 규칙을 따른다.
